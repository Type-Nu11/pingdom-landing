# Pingdom landing page

브랜드 소개 → 장소 발견 → 정보 확인 → 방문 준비 → 경험 공유 → 운영 도구 → AI → 팀 소개 순서의 정적 랜딩페이지입니다.

## 로컬 실행

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

프레임워크, 외부 API, 빌드 과정 없이 동작합니다. HTML은 콘텐츠, CSS는 레이아웃·반응형·모션, JavaScript는 기능 탭과 스크롤·포인터 반응을 담당합니다.

## 인터랙션

- 주요 기능 바로가기: 발견·확인·방문·기록의 독립 구간으로 이동합니다. 제목·설명·화면은 항상 보이며, 스크롤에 따라 숨기거나 교체하지 않습니다.
- 데스크톱 기능 구간은 각각 260svh입니다. 두 기기는 실제 크기의 90–100% 범위에서 정착하고, 브랜드 색 경로가 스크롤에 따라 이어집니다. 화면 확대는 사용자가 기기를 선택했을 때만 모달로 실행합니다.
- 900px 미만 또는 동작 줄이기 설정에서는 스크롤 고정을 해제하고 일반 문서로 표시합니다. 이번 재구성의 시각 검증 범위는 데스크톱입니다.
- 탭 방향키·Home·End 탐색 및 키보드 접근.
- 기존 히어로 입자 인트로·하프톤 포인터 반응을 유지합니다. 본문 모션은 제품 이미지와 장식 경로에만 적용하며 제목·설명·컨트롤에는 적용하지 않습니다.
- 상점주·관리자별 3가지 기능 화면 선택 및 확대 모달. 원본 크기 보기, Escape 닫기, 포커스 복귀. 운영·AI 영역은 높이가 자동으로 늘어나는 일반 문서이며, 처음부터 탭과 본문을 사용할 수 있습니다.
- 상점주 정보·방문자 경험·운영 도구를 구분해 정보의 출처를 설명합니다.
- Pingdom AI: 질문 선택, 장소 카드와 응답 전환. 상권 컨설팅: 성수동·카페를 고정된 분석 대상으로 표시하고, 카드형 리포트와 방문 흐름 그래프로 소개. 지역·업종 변경 입력은 제공하지 않음.
- 이름 목록에서 7명 팀원 선택, 발표자료 프로필과 담당 업무 상세. 김일강·이용인 사진 연결은 사용자의 최신 교정 요청 반영.
- 인트로 이후 PingDom 로고를 0.9초에 걸쳐 하프톤 점으로 전환합니다. 마우스·펜 주변의 점은 입자처럼 흩어져 일렁이고, 포인터가 떠나면 정렬된 로고로 돌아옵니다. `halftone-renderer.mjs`는 원본의 명암·알파를 최대 16,000개의 GPU 점으로 샘플링하며 DPR을 1.5로 제한합니다. `ring-flow.mjs`는 입력과 프레임 수명주기를 담당합니다. 정적 상태·화면 밖·비활성 탭에서는 렌더링을 멈추며, 동작 줄이기에서는 정적 하프톤을 표시하고 GPU 실패 시 원본 이미지로 복구합니다.
- 첫 화면 하단 중앙의 스크롤 화살표로 제품 소개 섹션으로 이동하며, 푸터 연락처는 메일 링크로 연결됩니다.
- 첫 접속에는 중앙의 사용자 제공 심볼과 `pingdom.` 문구가 약 1초 동안 함께 등장 → 완전 표시 상태로 1초 유지 → 로고와 글자 표면의 입자 분해 → 휘어지는 다층 흐름 → 링 표면 응집 → 제목과 메뉴 순서로 약 7.8초의 인트로를 재생합니다. 건너뛰기 버튼은 없으며, Escape·Tab·스크롤 입력과 동작 줄이기·뒤로 가기·하위 섹션 직접 진입은 즉시 본문으로 연결합니다. 이미지 준비 실패나 GPU·모듈 로딩 실패 시에도 본문을 복구합니다.
- 동일한 글자 비트맵에서 텍스트 표면과 입자의 출발점을 추출하고, 원본과 픽셀이 같은 링 WebP에서 도착점과 색을 추출합니다. WebGL에서 입자 위치·분해 경계·재질 전환을 계산합니다. 모바일은 입자 수와 잔광 수를 줄이고, 해상도 배율은 최대 2배로 제한합니다. 투명한 효과의 렌더 패스는 생략하며 종료·중단 시 프레임 루프와 GPU 자원을 해제합니다.
- 모션 참고: [Codrops — Emissive Dissolve Effect](https://tympanus.net/codrops/2025/02/17/implementing-a-dissolve-effect-with-shaders-and-particles-in-three-js/). 입자와 재질의 경계를 공유하는 원리를 참고했습니다. 텍스트의 분해 시점과 입자 발생 시점을 맞추고, 입자의 속도에 따라 잔광 길이를 바꿉니다. 서로 다른 곡률의 흐름은 도착할수록 링 표면으로 퍼지며 감속합니다. 빛 번짐은 1/4 해상도에서 계산하고, 금속 표면은 위치별 입자가 도착한 뒤 나타납니다. 참고 데모의 코드나 자산은 포함하지 않습니다.

## 자료와 표현

- 사용자 제공 발표자료 26쪽과 포트폴리오 58쪽을 기준으로 작성.
- 사용자 제공 7개 시각 레퍼런스의 큰 타이포, 비대칭 구도, 입체 소재, 강한 색 대비를 반영.
- 실제 앱·웹 화면과 7명 팀 담당 업무는 포트폴리오에서 확인. 프로필 사진은 발표자료 26쪽을 사용. 이름·역할의 최종 기준은 포트폴리오 57–58쪽.
- 소비자 Pingdom AI와 사업자 AI 컨설팅을 구분.
- 다운로드, 로그인, 예약, AI 호출은 연결하지 않은 소개용 사이트.

## 검증

- JavaScript 구문 검사, 로컬 파일·앵커·중복 ID 검사 통과.
- 이번 본문 재구성의 브라우저 시각 검증 범위는 PC 웹 1440×900·1280×720입니다. 이전 모바일 검증 결과는 새 구성의 검증을 대신하지 않습니다.
- 마우스 클릭, Enter, Home, End로 기능 내용·화면 전환 확인.
- 브라우저 콘솔 오류 및 로드 완료 이미지의 깨짐 없음.
- 실제 기기·서비스 API 연동·전체 E2E 테스트는 수행하지 않음.

원본 생성 비주얼과 글꼴 정보는 ASSETS.md를 참고하세요.

## 브라우저 피드백 반영

- 상단 영문 보조 문구, 중복 설명과 핑크 띠 제거. 주요 기능의 네 구간에는 읽는 순서를 안내하는 번호를 표시합니다.
- AI 두 서비스의 보조 설명, 운영 화면 하단 캡션과 장식 화살표 제거. 푸터 링크는 “처음으로”로 표기.
- 제품 소개: 발견·확인·방문·기록의 순서로 실제 앱 화면과 설명을 함께 배치합니다. 본문은 항상 유지하고 기기의 자세와 장식 경로에만 스크롤 모션을 적용합니다.
- 신뢰 정보: 상점주 제공 정보·방문자 경험·운영 도구를 구분해 정보의 출처를 설명합니다.
- 운영 화면: 기능 선택 목록과 실제 웹 화면을 나란히 배치하고 원본 크기 확대 제공.
- AI: 발표자료의 대화·추천·리포트 흐름을 HTML/CSS로 다시 구현하고 두 서비스의 사용 맥락 구분.
- 팀: 검은 사진 배경을 제거하고 테두리 없는 원형 프로필·이름·담당 업무를 밝은 단일 지면으로 구성.

AI 영역은 스크린샷이 아닌 네이티브 웹 요소로 구현했습니다. 장소 이미지·대화·리포트 그래프는 소개용 예시이며 실제 검색이나 분석 API를 호출하지 않습니다. 상권 컨설팅을 선택하면 제목도 함께 전환됩니다.

## 원본 이미지와 표시 품질

- 앱 화면 8개는 포트폴리오에 포함된 1800×3680 원본 PNG를 직접 추출했습니다. 일반 화면에는 960px WebP 미리보기를 표시하고, 확대할 때 PNG 원본을 불러옵니다.
- 상점주·관리자 화면 6개는 포트폴리오에서 1863–2908px 너비 원본 PNG를 직접 추출했습니다.
- 화면 내 문구를 재생성하지 않고 원본 그대로 표시하며, 확대 모달에서 원본 크기로 볼 수 있습니다.
- 앱 미리보기는 각 기능 구간에 고정해 두고, 해당 구간에 가까워지면 로드·디코딩합니다. 운영 화면은 탭에 포인터를 올리거나 키보드 포커스를 옮기면 미리 준비합니다. 작은 프로필 사진과 AI 장소 사진은 해당 영역에 접근할 때 준비하며, 첫 화면에서 모든 원본 PNG를 다운로드하지 않습니다.
- 운영·팀·확대 화면은 표시할 이미지의 디코딩이 끝난 뒤 교체하며, 이전 선택의 지연 응답은 무시합니다. 앱의 두 이미지와 설명은 탭으로 교체하지 않고 각 기능 구간에 함께 표시합니다.
- 중복 이미지 요청을 합치고 디코딩 캐시는 최대 4개를 유지합니다. 로딩 중 이전 내용을 숨기며, 실패하거나 15초가 지나면 다시 시도할 수 있습니다.
- AI 제목과 푸터는 웹 타이포그래피로 구성하며, 헤더 로고는 사용자의 요청으로 제거했습니다.
- 첫 화면은 원본 레퍼런스의 대형 타이포그래피·중첩 구도·입체 소재를 기준으로 전면 재구성했습니다. 검은 바탕의 자주빛 배경에 리본형 3D 비주얼을 중앙 배치하고, 핵심 문장을 대각선으로 이어갑니다. 도시 사진·핀·구체·궤도 장식은 화면에서 제거했습니다. 배경과 조형은 포인터에 서로 다른 깊이로 반응하며 모바일에서는 세로 구도로 배치합니다.

## 이미지 전환 회귀 검증

```sh
node --test tests/panel-images.test.mjs
```

지연 응답의 역전, 두 이미지의 동시 교체, 디코딩 완료 대기, 이전 요청의 실패, 재시도, 모달 닫기, 요청 재사용·캐시 제한, 타임아웃을 확인합니다. DOM/Image 대역으로 완료 순서를 제어하는 단위 테스트이며, 실제 네트워크 속도 측정이나 전체 E2E 테스트를 대신하지 않습니다.

## 인트로 회귀 검증

```sh
node --test tests/hero-intro.test.mjs
```

인트로 종료·중단 후 스크롤 잠금·임시 효과·프레임 루프·GPU 자원 정리, 지연 이미지 도착, 디코딩·GPU·모듈 실패 시 복구, 동작 줄이기·직접 진입 생략을 DOM/Animation/렌더러 대역으로 검증합니다. 실제 셰이더와 모션·최종 배치는 브라우저에서 별도로 확인합니다.

## 성능 최적화 자산 관리

하프톤 수명주기 회귀 검증은 `node --test tests/ring-flow.test.mjs`로 실행합니다. 포인터 이탈·저프레임 복귀, 중복 RAF 방지, 정적 resize, 동작 줄이기, 지연 decode·GPU 실패·이벤트 정리를 대역으로 검사합니다. 실제 GPU 출력은 PC·모바일 브라우저에서 별도로 확인하며 FPS 측정값을 대신하지 않습니다.

```sh
python3 -m venv .asset-tools
.asset-tools/bin/pip install Pillow==11.3.0 'fonttools[woff]==4.60.2'
.asset-tools/bin/python scripts/optimize-assets.py
```

화면 문구나 원본 이미지를 수정하면 위 스크립트로 표시용 자산을 다시 생성합니다. 글꼴은 HTML·CSS·JS·MJS의 문구와 ASCII를 포함하며, 가변 축과 사용 글리프의 보존을 검사합니다. 별도 데이터 파일이나 외부 콘텐츠를 추가할 때는 글꼴 수집 대상도 확장해야 합니다. 생성된 자산은 저장소에 포함하므로 배포 서버에서 Python을 실행하지 않습니다.

- 앱 미리보기 8개 합계: 15.11MB → 3.90MB. 960px로 축소한 비트맵을 무손실 WebP로 인코딩합니다.
- 글꼴: 2.06MB → 100.7KB. 현재 사이트에서 사용하는 문자만 포함합니다.
- 링·AI 장소 이미지: 원본 해상도와 RGBA 픽셀을 유지한 무손실 WebP로 변환합니다.
- 인트로: 입자·잔광·번짐과 글자·재질이 보이는 구간에만 해당 렌더 패스를 실행합니다. 타이밍과 입자 수는 유지합니다.

수치는 파일 바이트 기준이며 실제 다운로드 시간·FPS·Core Web Vitals 측정값은 아닙니다.

```sh
node --test tests/hero-intro.test.mjs tests/panel-images.test.mjs tests/ring-render.test.mjs
```

GPU 대역 테스트는 구간별 draw 호출과 기본 framebuffer 복귀·정리만 확인합니다. 실제 GPU 출력 검증은 브라우저에서 수행합니다.

## Vercel 배포

공개 주소: https://pingdom-landing.vercel.app/

`vercel.json`은 빌드·의존성 설치 없이 `dist`를 정적 배포하도록 설정합니다. `.vercelignore`는 배포 파일을 `dist`와 설정 파일로 제한하며, 원본 PNG는 확대 기능과 기존 자산 경로를 위해 유지합니다.

```sh
npx --yes vercel@61.0.0 link --yes --project pingdom-landing --scope azunox9-3685s-projects
npx --yes vercel@61.0.0 deploy --prod --yes --scope azunox9-3685s-projects
```

`.vercel` 연결 정보와 `.env*`는 커밋하거나 정적 사이트에 포함하지 않습니다. 기존 `.openai/hosting.json`은 이전 Sites 배포 기록이며 Vercel 배포에는 사용하지 않습니다.
